## Behavioural contract (source 6, authored)

### B1 — FSM shift requests: input.ShiftInto / ShiftUp / ShiftDown

The game never writes transmission.Gear. INPUT_GearChange / INPUT_HShifter write input.ShiftInto (int: -1 = R, 0 = N, 1..5); INPUT_ShiftUpDown writes ShiftUp/ShiftDown = true. NWH's ManualShift consumes them each update; ShiftInto's 'no request' sentinel is -999 (stub :91) and anything > -100 is a request (stub :341).

- relied on by: game FSMs (196 + 14 + 14 writes), the tuning mod's shift controller
- stance: **keep** · milestone A1
- members: `NWH.VehiclePhysics2.VehicleController::input.ShiftInto`, `NWH.VehiclePhysics2.VehicleController::input.ShiftUp`, `NWH.VehiclePhysics2.VehicleController::input.ShiftDown`
- test sketch: Drive the SPO transmission with the exact FSM write sequences from template_dump (R, N, 1..5 one-shots; H-shifter hold/release; up/down pulses) and assert the engaged gear after each; a request is consumed exactly once; the -999 sentinel never shifts; an out-of-range request (e.g. 9 on a 5-speed) is clamped/ignored and gear index stays valid.

### B2 — Gear list layout [reverse..., 0 (neutral), forward...] and the Gear index

TransmissionComponent.gears is a List<float> laid out reverse ratios first, then 0 for neutral, then forward ratios (stub :299); Gear is -1.. for reverse, 0 neutral, 1.. forward, mapped onto that list. NWH indexes gears[gearIndex] unguarded.

- relied on by: the tuning mod (gear ratio editing, 12-gear configs), CheckTag FSM (finalGearRatio)
- stance: **keep (layout) / must-not-have (unguarded index)** · milestone A1
- members: `NWH.VehiclePhysics2.Powertrain.TransmissionComponent::gears`, `NWH.VehiclePhysics2.Powertrain.TransmissionComponent::Gear`, `NWH.VehiclePhysics2.VehicleController::powertrain.transmission.finalGearRatio`
- test sketch: Property test: for random gear lists (1-3 reverse, 1-12 forward) and random shift sequences, the gear index always maps inside the list; shrinking the list while in a high gear clamps instead of throwing.

### B3 — Shift delegate reassignment on transmissionType change

NWH reassigns shiftDelegate (Manual/Automatic/CVT) whenever transmissionType changes (stub :318-326, :487-495), silently replacing any delegate a mod installed. CheckTag writes transmissionType (28 writes).

- relied on by: nothing should — the tuning mod needed a delegate guard because of it
- stance: **must-not-have** · milestone A1
- members: `NWH.VehiclePhysics2.Powertrain.TransmissionComponent::shiftDelegate`, `NWH.VehiclePhysics2.Powertrain.TransmissionComponent::transmissionType`, `NWH.VehiclePhysics2.VehicleController::powertrain.transmission.transmissionType`
- test sketch: Toggle transmissionType through every value 1000x with an SPO shift policy installed; assert the policy object is never replaced and no shift happens as a side effect of the toggle.

### B4 — Automatic gear skipping (the 12-gear 'launch from gear 8' bug)

NWH's AutomaticShift can jump several gears at once (stub :355-390), e.g. launching a 12-speed from gear 8.

- relied on by: nothing — a known bug class
- stance: **must-not-have** · milestone A1
- members: `NWH.VehiclePhysics2.Powertrain.TransmissionComponent::UpshiftRPM`, `NWH.VehiclePhysics2.Powertrain.TransmissionComponent::DownshiftRPM`
- test sketch: No-hunting grid: every (gear count 4..12) x (throttle 0..1) x (load) launch from standstill starts in gear 1 and never changes by more than one gear per shift event (kickdown excepted, bounded and explicit).

### B5 — Live powertrain relinking: Output / OutputB

PowertrainComponent.Output (and DifferentialComponent.OutputB) can be reassigned at runtime to re-route torque (stub :152, :539); the tuning mod rewires drivetrain layouts live.

- relied on by: the tuning mod (layout rewiring)
- stance: **keep** · milestone A2

- test sketch: Layout rewiring pass: switch FWD -> RWD -> AWD -> back while driving (harness), assert torque reaches exactly the wheels of the active layout, no NaN, no lost/duplicated torque (sum of wheel torques == driveline output within tolerance).
