# Crash report — 2026-10-04 (~20:14), native crash during save load

**Status (0.6.3): both hardening items implemented and harness-tested (README "Changes in 0.6.3-alpha" items 2–3). Root cause still unknown (native, mod inert); the user-side isolation steps below still apply if it recurs.**

**For the 0.7.0 rework pass: investigate this crash; the user hit it right after the 0.6.0 release-prep build.**

## What happened

- Unity's crash handler intercepted a **native crash** while the game loaded a save: `LoadLevelAsync: Game` had just run, and the game was mid-way through its **save-content spawn wave** (hundreds of `Instantiate`s — cassettes, headlights, gauges, truck wheels, an engine item "7L V8 355HP 569Nm Gasoline", etc. — see the "Rigidbody already added" spam in the excerpt).
- **No managed exception was logged before the crash** (no Mono stack, no BepInEx error). The stacktrace is entirely native `UnityPlayer` frames; the fault details live only in `crash.dmp` (1.5 MB, Windows minidump, not readable as text).
- Immediately before the crash the log shows the game's own warnings: `Couldn't create a Convex Mesh from source mesh "wheel_v5_FL.024" within the maximum polygons limit (256). The partial hull will be used.` (wheel mesh hull creation — a physics step) and the spawn spam.

## Mod state at the time (from the crash Player.log)

- `Apocalypter Vehicle Tuning 0.6.0` loaded; **every category OFF** (`Steering: off | suspension: off`); telemetry off; the panel was never opened (no blocker activity). The only mod activity was the tuner's read-only capture scan, which logged three healthy captures (Duke/Outrider/Rustliner, stock 5-speed lists, `layout=ok`).
- Also loaded: `Apocasetter 2.0.7` and **`Apocapatrol 1.20.3`** (newly installed by the user the same day — enemy patrol/conveyor spawning).

## Assessment (not conclusive)

No evidence implicates this mod: it was inert at the time, and there is no managed exception. The crash is native, during the game's own physics-heavy spawn wave, with two new variables in play (Apocapatrol 1.20.3, Apocasetter 2.0.7). Candidate causes: a game-side PhysX/mesh-hull fault, the spawn storm itself, or Apocapatrol's convoy spawning.

## Requested hardening for 0.7.0 (cheap insurance)

1. **Pause the tuner's 2 s scan while Unity is loading/spawning heavily** — e.g. skip `ScanVehicles()` for the first ~5 s after `SceneManager.sceneLoaded`, and skip a scan tick when a large number of new objects appeared (rough heuristic: `Object.FindObjectsOfType<VehicleController>().Length` grew by more than 2 since the last tick → defer one tick). Captures stay read-only, but staying out of the spawn wave entirely is strictly safer.
2. Keep every capture/apply path exception-guarded per category (the `PurgeDead`/null-guard style) so a mid-spawn half-initialised vehicle can never take the whole tuner down — (0.6.3 note: this was not accurate — the 0.6.2 tuner had no exception handling at all; both items are implemented in 0.6.3, see README "Changes in 0.6.3-alpha").

## User-side steps (given to the user)

1. Retry loading the same save — if it loads, the crash was transient.
2. If it crashes again in the same spot: disable Apocapatrol (move its DLL out of `BepInEx\plugins`) and retry — that isolates the newest external variable.
3. If it still crashes with only our mod + Apocasetter: save the next `Crash_*/` folder (the `crash.dmp` is the valuable part) and send it with the report.
